### Matriz de Comportamiento: Garbage Collector vs Tkinter

| Concepto Arquitectónico | Descripción del Mecanismo | Ciclo de Vida en RAM (El Peligro) | Solución / Ejemplo en Código |
| :--- | :--- | :--- | :--- |
| **Recuento de Referencias** | El sistema de rastreo de Python. Cada objeto en memoria tiene un "contador". Si otra variable o estructura lo usa, el contador sube. Si se deja de usar, baja. | **Muerte súbita:** Cuando el contador llega a `0`, el Garbage Collector ejecuta el objeto inmediatamente para liberar espacio. | `x = "Hola" # Ref = 1`<br>`y = x # Ref = 2`<br>`del x, y # Ref = 0 (Destruido)` |
| **Variables Locales** | Variables declaradas directamente dentro del bloque de un método o función. | **Efímero:** Nacen al ejecutar el método y mueren (Ref = 0) en el milisegundo exacto en que la función hace `return` o termina. | ❌ **(Crashea UI):**<br>`def render(self):`<br> `  logo = PhotoImage(...)`<br> `  Label(image=logo)` |
| **El "Engaño" de Tkinter** | Tkinter no dibuja la interfaz, delega la tarea a una librería externa en C (Tcl/Tk) pasándole la dirección de memoria de tu variable. | **Pérdida de Sincronización:** Python borra tu variable local porque *él* ya no la usa. Tcl/Tk intenta leer esa memoria para dibujar la pantalla y encuentra un vacío (imágenes invisibles, botones rotos). | *No aplica código. Es un fallo de arquitectura por ignorar que C y Python no comparten el Garbage Collector.* |
| **Atributos de Instancia** | Variables atadas al objeto padre (`self`). Actúan como un ancla que mantiene el contador de referencias en `1` o más. | **Persistente (El Blindaje):** Su ciclo de vida es idéntico al de la clase. Mientras la Ventana (la instancia) exista, la variable y la imagen existirán. El GC no las tocará. | ✅ **(Arquitectura Segura):**<br>`def render(self):`<br> `  self._logo = PhotoImage(...)`<br> `  Label(image=self._logo)` |
